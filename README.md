# Smart-metering sizing benchmark (Databricks Asset Bundle)

Runnable implementations of the use cases behind two Databricks cost models for a smart-metering platform
(an **ANZ** market model with 9 use cases and a **USA** market model with 24 use cases plus weekly forecast-model training), used to **measure** the inputs the models
had to estimate: minutes per run, cluster counts per meter tier, and the serverless DBU rating.

Everything runs on synthetic data generated in your own workspace. Nothing customer-specific is included.

| | |
|---|---|
| `databricks.yml` | Bundle: variables (catalog, schemas, benchmark scale) and the `dev` target |
| `resources/jobs.yml` | One job per use case / compute variant + two orchestrators (generated by `scripts/gen_jobs.py`) |
| `resources/warehouses.yml` | Serverless SQL warehouses (X-Small / Small / Medium) for BI and reporting workloads |
| `src/` | Notebooks: data generation, ingestion, ANZ batch use cases, USA analytics use cases, report |
| `docs/METHODOLOGY.md` | How the benchmark maps to the cost model, and its limits - read this first |
| `docs/USE_CASE_MAP.md` | Customer use case -> notebook -> model cost line |
| `docs/model_assumptions.csv` | What each cost model assumed (nodes, minutes, runs/day, DBU rating) |
| `docs/RESULTS.md` | Measured results from the reference run |

## Quick start
```bash
# 1. authenticate and point the target at your workspace (edit workspace.host in databricks.yml)
databricks auth login --host https://<your-workspace>.cloud.databricks.com --profile bench

# 2. set a catalog you can CREATE SCHEMA in
databricks bundle deploy -t dev -p bench --var catalog=<your_catalog>

# 3. generate data (~5 min each) and land the JSON batches used by the ingestion tests (~2 min)
for j in gen_data_anz gen_data_usa land_files_anz land_files_usa; do databricks bundle run $j -t dev -p bench; done

# 4. run every use case, one job at a time (each job run is billed separately)
databricks bundle run bench_all_anz -t dev -p bench
databricks bundle run bench_all_usa -t dev -p bench

# 5. a few hours later (billing system tables lag), build the model-vs-measured report
#    open src/90_report.py in the workspace and run it, or:  databricks bundle run report -t dev -p bench
```
Scale is controlled by bundle variables, e.g. `--var n_interval_meters=500000` to test linearity. Results land in
`<catalog>.<schema>.bench_results` (runtime per step) and `report_model_vs_measured`.

Requirements: Unity Catalog, serverless jobs and serverless SQL warehouses, permission to read `system.billing.usage`
(for DBUs), and a runtime-17.3 classic cluster option. The reference run used AWS (m5d instances) - see the limits in `docs/METHODOLOGY.md`.

## Tests
`uv run --with pytest pytest tests -q` - static checks that the generated job YAML is current, every cost-model row points to a
real job/step, and every notebook parses.

## Adding a use case
1. Add `src/NN_my_use_case.py` (use `common.params`, `common.Bench`; time with `with b.step("name") as s:`).
2. Add it to `scripts/gen_jobs.py` and run `python3 scripts/gen_jobs.py > resources/jobs.yml`.
3. Add a row to `docs/model_assumptions.csv` so the report compares it with the model.
